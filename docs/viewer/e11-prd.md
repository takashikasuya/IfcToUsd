# PRD: 大規模フェデレーションモデル最適化

更新日: 2026-08-26  
対象: Epic E11 (#78)、性能前提 E10-6 (#63)

## 1. 背景と課題

`files/kawasaki-model.ifc`（192 MB、7,267 meshes）では、正しさを維持した変換・表示は
できるが、ASCII USD、GLB の頂点重複、付加アセットの直列ロード、7,267 draw calls が
大規模利用を妨げている。E11 は計測可能な性能予算を先に固定し、成果物、配信、描画の
順でボトルネックを除く。

基準値は `ifc2usd benchmark` の同一マシン3回中央値を正とする。2026-08-26 の単発値は
USDC 78.89 MiB、cold open 1.15秒、GLB 103.71 MiB、初回メッシュ 7.72秒、全アセット
18.81秒、7,267 draw calls。voxelize 2,912.49秒は #63 の回帰候補として先に調査する。

## 2. 目的

- 大規模モデルの既定正本を高速に開けるバイナリ USD とする。
- GLB の構造的重複と転送量を削減する。
- メッシュを先に操作可能にし、付加アセット失敗を基本操作から分離する。
- 選択、階層、マテリアル、GUID、デジタルツイン機能を維持しながら描画負荷を下げる。
- すべての改善を再現可能なテストと性能差分で判断する。

## 3. 対象外

- IFC/USD の意味や階層を変える非互換な簡略化。
- CDN、外部 SaaS、認証情報のブラウザ配布。
- E5-2 OpenVDB、E6-1/2 3D Tiles、E11-7 フェデレーション分割の今期実装。
  これらは依存技術または前段の性能結果を確認してから再評価する。

## 4. 成功指標

| 指標 | 受け入れ基準 |
| --- | --- |
| USD | 既定 `.usdc`、78.9 MiB以下、cold open 3回中央値1秒以内 |
| voxelize | #63で工程別原因を特定し、3回中央値300秒以下を暫定予算とする |
| GLB頂点 | 3,726,610以下（現状比30%以上削減） |
| GLB転送量 | 再インデックス後サイズの60%以下（meshopt導入時） |
| 初期表示 | GLB描画後すぐ選択・ツリー操作可能。付加アセットを待たない |
| 描画 | Kawasakiで200 draw calls以下、frame time p95を改善 |
| 品質 | UsdValidation error 0、GUID/階層/PBR/bounds/選択E2Eを維持 |

## 5. 要件と実施順序

1. **計測ゲート**: #71（完了）で cold process/browser、RSS、成果物、描画指標を記録する。
2. **性能回帰**: #63 で USD open、要素抽出、LOD別 voxelize、JSON、PointInstancer を区間計測し、支配工程だけを最適化する。
3. **正本形式**: #70 で既定を `.usdc` にする。明示 `.usda`/`.usd` は維持する。
4. **GLB構造**: #72 で `(position index, normal)` をキーにロスレス再インデックスする。
5. **GLB圧縮**: #73 は #72 後に meshopt とオフライン decoder を評価・導入する。
6. **段階ロード**: #74 で Mesh を既定にし、voxels/SDF/twin/space voxels を初回利用時に一度だけロードする。
7. **描画集約**: #75 は #74 後に BatchedMesh 等を導入し、選択と可視性契約を維持する。
8. **選択安定性**: #77 は独立して早期対応し、対象 E2E を100回連続成功させる。
9. **将来ゲート**: #76、#31、#32、#28 は上記の実測後に投資判断する。

## 6. TDD・レビュー・PRワークフロー

各 Issue は1つの振る舞い単位・1 PRを原則とする。

1. Issue の受け入れ条件と計測条件を確認し、変更前ベースラインを保存する。
2. 最小の契約テストを追加して RED を確認する。性能項目は出力等価テストを先に固定する。
3. 最小実装で GREEN にし、対象テスト、関連回帰、全 pytest の順で検証する。
4. 大規模性能項目は同一マシン3回中央値で比較し、`metrics.json` と差分を PR に添付する。
5. PR 前に差分レビューを行い、正しさ、後方互換、メモリ上限、Windows/Linux、失敗分離を確認する。
6. CI 成功後に squash merge する。性能予算未達や品質差分があればマージせず Issue に戻す。

PR 本文には `Closes #N`、RED テスト、GREEN テスト、全体テスト、性能前後値、既知の制約を
必須記載とする。複数 Issue の抱き合わせや、計測なしの性能改善主張は行わない。

## 7. リスクと判断ゲート

- `.usdc` は差分レビューしにくいため、テストではステージ内容と UsdValidation を検証する。
- meshopt は decoder の vendoring、ライセンス、オフライン動作を導入条件とする。
- BatchedMesh は GUID 単位の選択・色・ghost/isolate を壊しやすい。機能 E2E を性能値より先に通す。
- voxelize 回帰の原因が USDC でなければ、形式変更と性能修正を同じ PR に混ぜない。
- 全体テストの既存 twin mock 失敗は別 Issue として追跡し、対象変更による新規失敗と区別する。
